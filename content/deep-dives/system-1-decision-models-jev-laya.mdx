## 😫 Nỗi Đau Sản Xuất: "The JSON Streaming Tax"

Trong kiến trúc Agent những năm qua, hầu hết các hệ thống kỹ thuật đều mắc phải một sai lầm tốn kém: **sử dụng một mô hình ngôn ngữ tự hồi quy (Autoregressive Generative LLM) khổng lồ chỉ để đưa ra một quyết định phân nhánh phần mềm**.

Hãy nhìn vào luồng thực tế của một kỹ sư backend:
1. Bạn có một người dùng gửi yêu cầu: *"Tôi muốn đổi vé máy bay bay ngày mai"*.
2. Bạn muốn hệ thống quyết định gọi API nào trong 3 hàm: `flight_change`, `refund`, hay `faq_help`.
3. Bạn mở kết nối Server-Sent Events (SSE), gọi GPT-4 hoặc Claude qua API.
4. Bạn ngồi chờ **2 đến 5 giây** để LLM sinh từng token text.
5. Bạn trả **$0.015 – $0.03** cho hàng nghìn token ngữ cảnh.
6. Khi nhận JSON về, thư viện Pydantic / Zod ném ra lỗi `500 Internal Error` vì LLM vô tình chèn thêm dấu ngoặc kép hoặc markdown ```json ```!

```
[Thực tế lãng phí khi dùng LLM làm bộ định tuyến quyết định]
State In ──> [ LLM 70B Tokens Generating... 2 - 5s ] ──> String: "```json { "action": "refund" }```"
                     ▲                                                    │
             Độ trễ cao, tốn tiền                                    Pydantic Parse Error!
```

Đây chính là **"JSON Streaming Tax"** — cái giá đắt đỏ mà các kỹ sư phần mềm phải trả khi ép một "nhà văn làm thơ" (Generative Reasoner) đi làm công việc của một "bàn chuyển mạch đường ray" (Deterministic Switchboard).

## ⚡ Sự Trỗi Dậy Của System 1: TypeSafe Jev & Laya (15/09/2026)

Vào giữa tháng 9/2026, thị trường ghi nhận sự ra mắt mang tính bước ngoặt của **TypeSafe Jev System 1**, đi kèm với bộ mô hình mã nguồn mở **Laya (`laya-multilingual`, `laya-typed-decisions`)**:

> **"Phần mềm không cần những đoạn văn giải thích dài dòng. Phần mềm chỉ cần Typed Decision Contract: State In → Calibrated Probabilities Out."**

### Sự khác biệt bản chất: Sinh văn bản vs Phân phối xác suất

| Tiêu chí | Generative LLM (System 2) | Decision Model (System 1 - Jev / Laya) |
| :--- | :--- | :--- |
| **Cơ chế hoạt động** | Tự hồi quy sinh từng token (Autoregressive $O(N)$) | **Một pass tính toán duy nhất (Single Forward-Pass $O(1)$)** |
| **Thời gian phản hồi** | 2.000 – 5.000 ms | **20 – 35 ms** (Nhanh gấp $\sim 100\times$) |
| **Chi phí mỗi request** | $0.01 – $0.05 | **Gần như bằng 0** (Chạy trên CPU hoặc GPU nhỏ) |
| **Đầu ra (Output)** | Chuỗi văn bản tự do (Dễ vỡ schema) | **Vector xác suất đã hiệu chuẩn** trên simplex $\Delta^K$ |
| **Rủi ro ảo giác** | Luôn tiềm ẩn | **Không có ảo giác sinh văn bản** |

## 🎯 Bản Chất Tin Cậy: Bẫy "Raw Softmax" & Huấn Luyện RLCD

Tại sao không dùng một bộ phân loại (Classifier) thông thường như BERT hay RoBERTa?
Vì softmax thô (Raw Softmax) của các mạng neural thông thường mắc phải **The Confidence Trap (Bẫy Tự Tin Thái Quá)**: Một mô hình có thể xuất ra xác suất $99.9\%$ cho một dự đoán hoàn toàn sai lầm khi gặp dữ liệu lạ ngoài phân phối (Out-Of-Distribution).

### RLCD: Reinforcement Learning for Calibrated Decisions
Jev và Laya giải quyết bài toán này bằng kỹ thuật **RLCD**, huấn luyện mô hình dựa trên **Strictly Proper Scoring Rules** (Quy tắc tính điểm chuẩn tắc như hàm mất mát Brier):

$$\text{Brier Score} = \frac{1}{N} \sum_{i=1}^N \sum_{k=1}^K (p_{ik} - y_{ik})^2$$

* **Cơ chế phạt bậc hai (Quadratic Penalty):** Nếu mô hình đoán xác suất $99\%$ mà thực tế bị sai, nó sẽ bị phạt cực kỳ nặng nề về điểm thưởng.
* **Độ tin cậy được hiệu chuẩn (Calibrated Confidence):** Khi mô hình nói xác suất là $80\%$, thì chính xác trong 100 lần nó đưa ra dự đoán này, có 80 lần nó đúng và 20 lần nó sai.
* Nhờ đó, kỹ sư phần mềm có thể **viết logic nghiệp vụ dựa trên ngưỡng tự tin thực sự** mà không sợ rủi ro bất ngờ.

## 🧩 4 Mẫu Hình Tích Hợp System 1 $\times$ System 2 Trong Agent

Các hệ thống Agent hiện đại cuối năm 2026 không loại bỏ LLM, mà phối hợp nhịp nhàng giữa **System 1 (Phản xạ siêu tốc)** và **System 2 (Suy ngẫm chuyên sâu)**:

```
                                  [ Yêu cầu từ Người Dùng ]
                                              │
                                              ▼
                             ┌─────────────────────────────────┐
                             │    SYSTEM 1 (Jev / Laya)        │
                             │ • Độ trễ: 30ms | Chi phí: $0    │
                             │ • Định tuyến ý định & Công cụ   │
                             └────────────────┬────────────────┘
                                              │
                      ┌───────────────────────┴───────────────────────┐
         Độ tự tin CAO (≥ 0.85)                           Độ tự tin THẤP (< 0.85)
                      │                                               │
                      ▼                                               ▼
         ┌─────────────────────────┐                     ┌─────────────────────────┐
         │ THỰC THI API TRỰC TIẾP  │                     │ LEO THANG LÊN SYSTEM 2  │
         │ Không cần gọi LLM!      │                     │ Gọi o1 / Claude Sonnet  │
         │ Tốc độ < 50ms, $0 token │                     │ để suy luận đa bước     │
         └─────────────────────────┘                     └─────────────────────────┘
```

### 1. Dynamic Tool Pre-Filtering (Giải quyết nút thắt 50 công cụ)
* **Vấn đề:** Khi agent có 50+ công cụ, nhồi toàn bộ JSON schema vào context của LLM sẽ đốt mất 4.000+ token mỗi lượt và làm LLM bị "ngáo" (chọn nhầm công cụ).
* **Giải pháp:** Cho System 1 (<30ms) quét ý định người dùng trước, lọc lấy đúng 2 công cụ cần thiết nhất rồi mới nạp vào prompt cho LLM.

### 2. Conditional Escalation Ladder (Bậc thang leo thang có điều kiện)
* Với các tác vụ rõ ràng (chiếm 70–80% khối lượng giao dịch), System 1 đạt độ tự tin $\ge 0.85$ và tự động thực thi thẳng lệnh API mà không cần đánh thức LLM.
* Chỉ 20% các trường hợp mơ hồ hoặc tranh chấp mới leo thang (escalate) đến Frontier LLM đắt tiền.

### 3. Real-Time Output Guardrail (Cổng kiểm soát an toàn microsecond)
* System 1 đóng vai trò như bộ phanh khẩn cấp, quét token đầu ra với độ trễ 30ms để phát hiện vi phạm bản quyền hoặc rò rỉ dữ liệu cá nhân trước khi gói tin được gửi tới client.

### 4. Sub-Agent Dispatcher (Bộ điều phối nhánh công việc tự hành)
* Trong các hệ thống multi-agent, System 1 phân loại và chia việc cho các chuyên viên agent độc lập chỉ trong nháy mắt.

```
┌────────────────────────────────────────────────────────────────────────┐
│ LÀN 1: Rules & Code Heuristics (< 1 ms | $0 | Hoàn toàn xác định)      │

├────────────────────────────────────────────────────────────────────────┤
│ LÀN 2: Decision Models - System 1 (~30 ms | Chi phí ~0 | Calibrated)   │
│ • Jev, Laya: Phân nhánh xác suất, tiền lọc công cụ, định tuyến agent.  │
├────────────────────────────────────────────────────────────────────────┤
│ LÀN 3: Generative Reasoners - System 2 (Vài giây | $$ | Sâu sắc)       │

└────────────────────────────────────────────────────────────────────────┘
```
